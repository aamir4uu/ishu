Two images, as the master guidelines ask for: one banner and one in-line. Each
sits in the draft with descriptive alt text and an "Image Source" line directly
beneath it, hyperlinked to the image's own page.

## The files still need downloading and uploading

This draft was produced in an environment with restricted outbound access, so
`pexels.com` and `images.pexels.com` could not be reached and the image
**files** could not be downloaded or re-hosted. Every URL below was confirmed
through search and points at a real Pexels photo page, but the `![...]()`
markdown in the draft currently points at the photo page rather than at an
uploaded asset. The .docx carries a sized placeholder frame in each slot with
the alt text and the source link beside it.

For each image: open the source URL, download the file, upload it to the Hero
FinCorp media library, and replace the URL inside the `![alt text](...)`
markdown with the uploaded asset path. Leave the "Image Source" link underneath
pointing at the original Pexels page. That is what the checklist asks for, and
it is also what the Pexels licence expects.

Pexels is free for commercial use with no attribution required. The credit line
is there because the checklist asks for it, not because the licence demands it.

## Before upload

- Resize to the blog's banner and in-line widths, then compress. Target under
  150 KB each so the images do not drag Core Web Vitals.
- Export as WebP if the CMS accepts it.
- Keep the alt text as written. It is descriptive rather than keyword-stuffed,
  which is what the guidelines ask for.
- Check the "Image Source" hyperlink survives the CMS paste. It is the one
  checklist item that silently breaks on import.
